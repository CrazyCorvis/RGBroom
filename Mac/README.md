# RGBroom для macOS

Нативный интерфейс SwiftUI и общий C#/.NET 10 движок Windows-версии. Для оформления macOS 27 собирайте приложение Xcode 27: системные `NavigationSplitView`, sidebar, toolbar, формы, ColorPicker, меню и SF Symbols используют оформление установленной ОС, включая Liquid Glass. Светлая/тёмная тема, акцентный цвет и настройки доступности берутся из системы. На старых версиях macOS используется их системное оформление, без имитации стекла.

## Запуск

Откройте `artifacts/macos-arm64/RGBroom.app`. Среда .NET включена в приложение. Поддерживаемый минимум — macOS 14; сборка и интерфейс проверяются на текущем Mac. Для macOS 27 используйте Apple Silicon.

1. В разделе **Контроллеры** выполните поиск Wi-Fi/Bluetooth или добавьте IPv4 вручную.
2. Отметьте устройства и нажмите **Подключить** (`⌘K`).
3. Выберите режим в боковой панели (`⌘1`–`⌘5`). Питание — `⌘P`.
4. При первом использовании Bluetooth разрешите доступ. Для цветомузыки/фона разрешите **Запись экрана и системного аудио** в Системных настройках → Конфиденциальность и безопасность. После изменения разрешений может потребоваться перезапуск RGBroom.

Настройки приложения (`⌘,`) содержат ссылки на разделы разрешений.

## Возможности и отличия

| Функция | Реализация на Mac |
| --- | --- |
| Цвет, переход, цветомузыка, спектр, фон | Общий `LightEngine`, FFT и эффекты из `Source/` |
| Magic Home, WLED, Yeelight, Tuya LAN 3.3/3.4/3.5 | Общие сетевые адаптеры; проверяются локальными эмуляторами |
| Системный звук | ScreenCaptureKit, 48 кГц, стерео; общий звук приложений, без выбора отдельного выхода WASAPI |
| Фон | ScreenCaptureKit, выбранный дисплей, уменьшенный BGRA-кадр 128×72, общий алгоритм доминирующего цвета |
| ELK-BLEDOM / Triones | CoreBluetooth; устройства идентифицируются UUID этого Mac |
| ELK с альтернативными пакетами | Переключатель **Альтернативные пакеты ELK (handle 13)**: CoreBluetooth не раскрывает GATT handles, поэтому автоопределение Windows недоступно |
| Tuya local_key | Связка ключей macOS; JSON содержит только ссылку на ключ |

Подключение к реальным контроллерам и захват с выданными разрешениями требуют проверки на вашей конфигурации. Защищённый медиаконтент может исключаться macOS из захвата. BLE Mesh, Zigbee и ELK-BLEDOB не поддерживаются, как и в Windows-версии.

Настройки: `~/Library/Application Support/RGBroom/settings.json`; журнал: `errors.log` рядом. Можно перенести Windows JSON при закрытом приложении, но BLE нужно обнаружить заново на Mac, а ключи Tuya — ввести заново: DPAPI не переносится в Keychain. Выбор выхода Windows игнорируется. Если сохранённый идентификатор дисплея недоступен, выберите дисплей Mac.

## Сборка

Нужны Xcode с принятой лицензией (`sudo xcodebuild -license`) и .NET SDK 10. Для актуального дизайна macOS 27 нужен Xcode 27.

```sh
./Mac/build.sh
# Или сборка для Intel (на поддерживающей его macOS):
./Mac/build.sh x86_64
```

Скрипт компилирует Swift bridge, собирает C# и запускает общие self-tests на нативной архитектуре, публикует self-contained движок, собирает SwiftUI, добавляет иконку/лицензии и проверяет локальную ad-hoc подпись. Путь к нестандартному SDK можно задать как `DOTNET=/path/to/dotnet ./Mac/build.sh`. Приложение — в `artifacts/macos-<архитектура>/RGBroom.app`; отчёт — `Mac/.build/<архитектура>/test-report.txt`.

Self-tests создают только временные тестовые записи Keychain (удаляют после успешной проверки) и серверы на loopback. Не требуют реальных контроллеров и не запрашивают захват экрана или Bluetooth.

Для публичной загрузки нужно отдельно настроить Developer ID signing и notarization. Локальная ad-hoc подпись не является нотарификацией Apple.

## Архитектура

- `RGBroomApp.swift`, `Models.swift` — SwiftUI и модель состояния; связь с движком через JSON lines по stdin/stdout.
- `Program.cs` — локальный процесс `RGBroom.Engine`, команды интерфейса и события состояния.
- `native/Bridge.swift` — ScreenCaptureKit, CoreBluetooth, Security.framework; C ABI для .NET.
- `Capture.cs`, `BluetoothConnection.cs`, `Native.cs` — платформенные адаптеры.
- `RGBroom.Mac.csproj` подключает общие исходники из `Source/`, без WPF/WASAPI/Windows GATT.

Ключи не передаются в аргументах процесса; звуковые/видеоданные остаются в памяти процесса движка. Bluetooth и экран не запрашиваются до запуска соответствующей функции.

Рекомендации Apple: [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [Materials](https://developer.apple.com/design/human-interface-guidelines/materials).
